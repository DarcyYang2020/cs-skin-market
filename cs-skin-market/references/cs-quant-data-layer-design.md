## 2. 采集

**结论（用户 5 问定调）：**
1. **价格 × 在售量引擎合理**（去量后正确选择），但属"降维使用"——bid / spread / turnover 已采未用，是真金白银富矿（点差=流动性+情绪的直读）；
2. **日频 K 线为单一事实源**，时/周 K 一律派生（resample），不单独采集、不单独存储；
3. **执行层可成交性数据可采**：Tier-1 盘口（最佳买卖价+点差+挂单量+日成交）csQAQ 现即可日采累积；缺多档深度/成交明细（Playwright 增量）；**历史盘口不存在，只能从现在开始累积（时间成本，宜早）**；
4. **情绪改用市场内生信号**（替代 approx_sentiment 价格行为代理）：因子=点差 / bid 强度 / 日成交变化 / 在售量变化；时间线=v0 用价格/在售量可回测部分先预注册验证，同时积累 3-6 个月后 v1 加 bid/spread/turnover 因子（走 A2 三件套/四关）；
5. **外部·事件/社区 数据域取消**（用户拍板，不展开）。

**落库三缺口（工作量小）：**
- ① `price_history` 加 `price_source TEXT` 列（锚平台，collector 已知，一行迁移）；
- ② 每日点差 = **派生**（price_history.price − bid_history.buy_price，双侧都有日数据，先视图、性能不够再物化），不新采；
- ③ `bid_history` 补卖侧列（lowest_sell/sell_count）→ 完整订单簿快照。

## 3. 存储

- **分层**：原始层（高价值数据独立 `raw.db`，append-only，订单簿/成交/存世量原始值；价格历史不建，price_source 列够追溯）→ 加工层（market.db，权威数据，跨品闸门/锚定在此执行）→ 派生层（回放库/特征矩阵/时周K/点差视图，**一律可重建、不备份、git 不跟踪**）；
- **单一事实源三铁律**：①日 K 是唯一价格事实源；②每日点差=派生视图不单独存；③口径唯一权威（config taxonomy，C1 教训）；
- **技术选型**：保持 SQLite（240 品×日频远未到时序库门槛），分层用文件隔离不换引擎；
- **升级触发条件**（写进治理，满足再议）：①并发写冲突常态化 ②单库 >2GB 或查询退化 ③需多实例/多机。

## 4. 处理

- 四块：清洗（异常/缺失/重复/污染/源故障）、对齐（时间/键/多源/口径）、派生（特征/视图/矩阵/标注）、留痕与确定性；
- **三条铁律**：①可复现（清洗/派生函数确定性，同输入同输出，回放 patch 推广到全部规则）②可追溯（每次清洗/修正留痕：谁/何时/规则/原值→新值）③不污染原始（清洗在原始之上，原始层只增不改）；
- **规则配置化（已拍板）**：清洗规则（跨品闸门阈值/回滚开关、锚定优先级、污染剔除清单、新鲜度/缺失率阈值）进 `pipeline/config.py`（沿用 PARAM_REGIME 先例，规则带：参数/默认值/出处 decision-log/生效日期）；触警/回滚落 `data/cleaning_ledger.jsonl`（日期/规则/触警值/动作/受影响品数/原值→新值），进每日健康检查统计。

## 5. 治理

- **血缘（含具体实现，待③审计）**：
  - 行级：price_source + created_at + 采集批次标识；清洗台账 cleaning_ledger.jsonl；
  - 派生级：`data/provenance.jsonl` 或产物内嵌元数据（生成脚本/输入源[库+基线版本]/参数[引擎版本/seed/窗口]/生成时间戳/数据版本标记）；回放库重建记"基于哪个 market.db 快照 + backfill 批次"；
  - 数据版本：关键产物带版本快照（schema 版本 + 数据时点 + 口径定义）。
- **恢复演练（含具体实现，待③审计）**：
  - 脚本化固化 08-20 恢复动作：`references/drills/restore_from_backup.py`（.bak 恢复+行数校验）+ `rebuild_derived.py`（幂等重建派生库）；
  - 台账 `data/recovery_drill_log.jsonl`（日期/项/耗时/PASS-FAIL/重建后行数对比）；
  - 频率：每月一次全流程（备份→模拟删除→恢复→重建派生→校验），进健康检查；
  - 校验：PRAGMA integrity_check + 行数对比 + 抽样字段对比（防静默损坏）。
- **备份**：关键库（market.db/raw.db）每日 .bak 双副本；派生层不备份靠可重建；备份成功率进健康检查。
- **监控**：健康检查 + 钉钉告警 + 闸门触警统计 + 缺失率 + 新鲜度（上次成功采集距今）。

## 6. 分发

- 消费方：研究层（批量读派生层）、决策层（运行时查加工层）、评估层（历史+交易数据）、执行层（未来准实时通道）；
- **四条原则**：①只读消费（消费方不得写权威库）②**版本冻结**（研究回放必须基于冻结数据版本，防分析中数据变动——103 漂移病根）③派生隔离（_exp/回放库与生产库物理隔离）④口径一致（config 单一权威）；
- 差距：版本冻结概念最弱，为分发层第一优先补齐项；统一访问层**不做**（单机直连够用，schema 迁移纪律兜底）。
