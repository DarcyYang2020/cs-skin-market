## 2. 详细方案

### T0 · 真实情绪历史持久化缺口（P0-1 根因，数据层）

**第一性原理**：panic 信号族（93 信号，全系统最高胜率）的生产输入是贪婪指数逆向情绪；若该输入的历史不可复核，则「回放高胜率 → 生产可外推」的因果链断裂。预探针显示 `macro_history.greedy_index` 仅 2 天非空——先修数据，才能做 T1。

**检验设计**：
- 数据源：每日采集 `run_daily_collect.py`（csQAQ 每次返回约 60 天贪婪历史，`_persist_macro` 应可回填）。
- 步骤：连续 7 个采集日，检查 `macro_history.greedy_index` 非空天数是否单调增加且最终覆盖 ≥60 天；与当日 live 贪婪值核对。
- 判定：7 天后覆盖 ≥60 天且当日值一致 = PASS；持续 None / 覆盖不增长 = FAIL → 排查 `_persist_macro` greedy 路径或 csQAQ 上游字段变更（`market_macro.py:36-59`）。
- 产物：`data/_exp_greedy_backfill_check.json`（每日一行：date / non_null / coverage）。
- 决策含义：PASS → T1 可启动；FAIL → 修采集（数据层改动，不涉引擎），修后若回放情绪口径变化，重跑回放 + sync。

### T1 · 回放近似情绪 vs 生产贪婪映射一致性（P0-1）

**第一性原理**：若两个口径在「相同市场状态」下产出相近情绪分，panic 参数外推风险低；若系统性偏移（尤其恐慌桶），生产 panic 触发集合与回放不同构。

**检验设计**：
- 数据源：`macro_history.greedy_index`（T0 后积累 ≥60 天）+ `market_index`（366 天）+ 回放近似逻辑（`backtest_common.py:12-19` approx_sentiment）。
- 方法：逐日计算 `greedy_to_sentiment(greedy_index)` vs `approx_sentiment(index)`，按市场状态桶（V 型底 / 阴跌中继 / 中性 / 弱市）输出偏差分布。
- 判定：总偏差 |Δsent| 中位 ≤10 且恐慌桶（mkt_chg30≤-15）中位 ≤8 = PASS（口径可互换）；否则 panic 参数外推标记「待生产样本复核」，C 通道（min_filled14=20）达标前不作 panic 参数结论。
- 产物：`data/_exp_sentiment_caliber.json`。
- 注意：本项是观察级验证，不推翻 TH/情绪/牛熊定论。

### T2 · 2% 成本假设实证（P0-2）

**第一性原理**：回测净收益 = 毛利 - 成本；成本 = 价差 + 手续费 + 冲击。预探针显示 spread_pct 中位 3.15%、78% 样本 >2%——「2% 双边」对挂单买入可能是乐观假设。**第一步量化价差结构，第二步做成本阶梯，第三步用真实滑点校准（A1-4）。**

**T2A（只读，可立即执行）**：
- 数据源：`snapshots`（bid_highest / spread_pct / spread_avg，当前 72 条有效）join `price_history` 最新在售量。
- 方法：spread_pct 按在售量分桶（<50 / 50-200 / 200-500 / 500+）× 价格带（<100 / 100-1000 / >1000）→ 验证「低在售/高价格 → 价差更大」。
- 判定：低流动桶 spread 中位 > 高流动桶 ≥3pp = 成立 → 支持 F-4 分层成本；不成立 → 2% 假设维持。

**T2B（只读回放，可立即执行）**：
- 数据源：`references/run_item_backtest_full.py` 链路（只读回放，产物不覆盖标准文件，另存 `_exp`）。
- 方法：cost = 0.01/0.02/0.03/0.05 阶梯复跑（或对 332 信号用净收益线性换算：net(c) ≈ fwd14 - c），输出 win14/avg14 衰减曲线。
- 判定：3% 成本下 avg14 仍 >0 = 2% 假设保守可维持；3% 下转负 = 需分层成本建模（F-4 立项证据）。
- 产物：`data/_exp_cost_ladder.json`（含三件套口径：信号数不变 / 胜率 / 期望增量）。

**T2C（实盘积累，A1-4 承接）**：executions.advice_price vs exec_price 滑点 ≥20 条后统计；与 T2A/B 交叉验证。

### T3 · 流动性分桶——「在售 ≥15 即放行」是否足够（P1-1）

**第一性原理**：闸门 `0<supply_depth<15 降级`（`trend_health.py:671`）保护了「结构性无流动性」，但 15-50 的高价品（刀/手套）真实可成交深度可能 <1 件（挂单多为虚挂）。若低桶信号显著劣化，闸门下界需要重议。

**检验设计**：
- 数据源：回放 332 信号 join `price_history`（item_id + date → 当日 in_sale_count，只读）。
- 方法：按信号日在售量分桶（15-50 / 50-200 / 200-500 / 500+）× 价格带，对比 net14/win14 + **独立事件数**（±3 天聚类，J-1 口径）——单事件簇不能作结论。
- 判定：低桶 win14 差 ≥10pp 且 n≥30 且独立事件 ≥3 = 候选「分层在售下限」，走三件套 + A2 才可改参数；否则维持现状。
- 产物：`data/_exp_liq_bucket.json`。

### T4 · 吸筹机制替代解释——「潜伏」vs「追高」（P1-2）

**第一性原理**：供给收缩 + 价格上涨可能是「真吸筹（主力边拉边收）」也可能是「追高（散户接盘）」。预探针显示吸筹族 chg7>3% 桶 win 仅 43.8%（n=32）、-3~0% 桶最好（65.1%/+13.4）——与周期权重反转定论（洗盘最优/拉升最差）自洽。若「>3%」子集持续为负贡献，可提出**吸筹族加动量上限**的候选（与 S3 定义「7 日 |涨跌|≤3%」一致，`trend_leg_research.md`）。

**口径澄清（执行期更正）**：引擎 `supply_accum` 触发已含 7 日 `abs(chg7)<=3`（chg7 = current vs prices[-8]）；用 price_history 实证核对 26 条「被剔除信号」：引擎 7 日 chg 全部 ≤3（max 2.93），真实差异在 **8 日动量**（回放信号 chg7 字段实际为 8 日分母 prices[i-8]）——「一周前拉涨、近 7 日横盘」= 泵后横盘追高段。**正确候选 = 新增 chg8 特征门（8 日动量 >3% 禁买）**，原「chg7≤3% 上限」表述更正为 chg8。

**执行记录（已落地）**：
- 第一步（只读分桶，`data/_exp_accum_chg7_bucket.json`）：212 条吸筹族按 8 日动量五桶，`>3%` 桶 win 43.8%（n=32，events=10）→ 候选成立。
- 第二步（正式引擎 A/B，开关 `CS_ENGINE_SUPPLY_ACCUM_CHG8_CAP`）：见 §5 T4 正式 A/B 结果 → **全指标改善无劣化，已落地**（2026-08-10，ENGINE_VERSION v2-I13→v2-T4）。
- 合规：第二步走完三件套 + 文档同步（decision-log「第一性原理测试 P-1 正式引擎 A/B + chg8 门落地」）。

### T5 · 新品 90 天窗口截断失真（P1-3）

**第一性原理**：位置分（40%）与周期分（25%）都基于 90 日窗口；上市不足 90 天的新品窗口被截断，90d 分位从开盘价回落路径上天然偏高 → 低估区判断失真，且新品进不了 365d 回测（B-2 结构性约束已确认）。

**检验设计（只读 SQL，可立即执行）**：
- 数据源：`items.created_at` + `analysis_results`/price_history 计算的 percentile_90d。
- 方法：`created_at` 距今 <90 天的品 vs 老品，比较 percentile_90d / valuation_tier 分布。
- 判定：新品 pct 中位显著 >60（老品约 50）= 截断失真成立 → 展示层建议「上市不足90天」标注 + 低权重提示（展示层改动，确认后实施）；不显著 = 关闭该项。
- 产物：`data/_exp_new_item_window.json`。

### T6 · 大户集中度 × 供给收缩交叉（P2-4）

**第一性原理**：`monitor_rank_snapshot`（每周 Top50 大户持仓）是独立于价格与在售量的供给侧证据。若「大户增持 + 在售收缩」= 真吸筹，14d 应显著高于「无大户变化 + 收缩」= 流动性噪音/惜售。

**检验设计**：
- 数据源：`monitor_rank_snapshot`（每周一，已有）+ 供给收缩信号（±3 天窗口对齐）。
- 方法：分组「大户增持 / 减持 / 无变化」× 信号 14d；周度样本，先积累 ≥12 周（约 2026-11）再判。
- 判定：增持 vs 减持桶 win14 差 ≥10pp 且每桶 n≥15 = 候选条件（进守卫/权重须三件套 + A2）；否则维持观察。
- 产物：`data/_exp_whale_cross.json`（积累型，脚本幂等追加）。

### T7 · 趋势腿 alpha 立项包（A2 三件套）

**第一性原理**：系统 buy 信号全为「恐慌抄底 + 均值回归」单策略族；非恐慌上涨段收益效率低（W2 30d 引擎 +5.33% vs S2/S3 候选 +22~31%，`trend_leg_research.md`）。alpha 空间候选 = 回踩腿 S2 + 吸筹腿 S3，落地前必须过 A2。

**检验设计**：
- 数据源：回放链路 + `build_market_context` 市场状态桶（路由门控表 v0：贪婪禁入 / 恐慌仅抄底 / 中性开 S2+S3 / 强牛回调桶）。
- A2 三件套：
  1. walk-forward：按市场状态（牛/熊/震荡）分折，前段拟合门控、后段 OOS 验证；
  2. 信号聚类：±3 天去簇（`backtest_methodology.signal_cluster_report`），独立事件 ≥3 才认；
  3. 置换检验：1000 次随机打乱日期，p<0.05。
- 通过标准：OOS win14 ≥70% 且 p<0.05 且独立事件 ≥3 且与现有族同日去重无冲突 → 可立项（新 P 系列族，注册 `SIGNAL_FAMILIES` + 路由门控）；否则维持观察。
- 产物：`data/_exp_trend_leg_a2.json`；脚本骨架：`references/trend_leg_a2.py`（未写，立项时创建）。
