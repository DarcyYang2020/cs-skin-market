# 大盘引擎完善方案 v1（2026-08-17，主路径第 (1) 步）

> 状态：已完成（A-D 已实现于 `pipeline/market_signal.py`、`market_period.py`；结论见 `two-day-synthesis.md`）。本文保留原方案。

> 依据：用户裁定主路径——(1) 先把大盘引擎彻底完善 → (2) 再研究大盘引擎能帮单品分析引擎什么 → (3) 单品分析提升后，再看对大盘引擎有无可修正的地方。
> 本文只做 (1) 的方案；(2)/(3) 仅在第七节列研究议程，不在本次执行。

## 一、"彻底完善"的边界定义

**大盘引擎的职责**（从用户历次裁定回溯）：说清四件事——① 现在处于哪个时期；② 大盘级该干什么（买/持/避）；③ 风险状态；④ 黑天鹅事件怎么响应。**它产出大盘级结论，不产生单品信号。**

**已完成、不重做**：M1 状态基座（chg 轴+TH+vol+广度+距高低点）、五时期定稿与落地（state_bucket / 典型区间 / 边界稳定性）、M2 等权基准、单品侧时期路由（v2-T13）、退出层与时期乘子（已验证证伪 → 结论=维持现状 hold21+cap0.8）。

**本次要做的缺口清单（= 验收清单 A-D）**：

| # | 模块 | 一句话 |
|---|---|---|
| A | 大盘自身信号 | 时期 → 大盘级动作（抄底/回调买/空仓/反抽陷阱）+ 该时期大盘自身前视期望（证据引用） |
| B | 黑天鹅事件响应 | 单日/3 日急跌检测 → 事件响应提示（组合层建议，不自动卖出） |
| C | 时期监测自动化 | 时期切换事件 + 当前时期持续天数 + 边界季度重验台账 |
| D | 大盘风险仪表 | vol20 / breadth5 / 距 60-180 日高低点 → 风险档位（低/中/高） |

**明确不做**：不触碰单品信号引擎（族/守卫/路由零改动，引擎无关纪律）；不做组合层时期乘子（已证伪 p=0.605）；不做时间型退出（已证伪 −73pp）。

## 二、模块 A：大盘自身信号（pipeline/market_signal.py）

- **输入**：生产库大盘指数（3 年历史已回填）→ 实时 chg180×chg30 → 时期；风险与广度字段取 M1 口径。
- **输出**：
  - `period`：五时期标签；
  - `market_action`：P→`buy_zone 抄底区` / S1→`hold_zone 持多区` / S2→`pullback_buy 回调买点区` / S3→`avoid 空仓区` / S4→`trap 反抽陷阱区`；
  - `period_forward`：该时期大盘自身 14d/30d 前视（**证据引用** `data/_exp_market_periods.json`，固定表非重算）；
  - `evidence_note`：一行证据文案（如 S2「大盘自身 30d 57%/+1.0、60d 55%/+4.3——二波前夜」）。
- **数据依据（已挖好，零新拟合）**：P 14d 91%/+13.8；S1 70%/+0.5 慢牛低波；S2 短平中正（60d +4.3）；S3 全期限负（14d 33%/−2.6）；S4 反抽（30d 28%/−3.0）。
- **展示**：dashboard 新增「📡 大盘信号」卡（时期+动作+前视证据）；单品报告研究提示区加一行大盘语境（复用 bucket，纯展示）。
- **验收**：5 时期映射 + 边界（chg30=−15、chg180=0）+ 卡片渲染测试；引擎行为零变更（回放产物逐字节不变）。

## 三、模块 B：黑天鹅事件响应信号

- **职责**：大盘单日/3 日急跌指纹检测 → 输出事件响应提示（**组合层建议，绝不自动卖出**；卖出仍走持仓止损矩阵）。
- **先预研后定规则**（`references/probe_crash_window_forward.py` 已写好未跑，批准后第一步就跑它）：
  - 指纹：单日 ≤−8% 或 3 日累计 ≤−12%（黑天鹅级，对应五合一/炼金冲击）；
  - 看历史窗口 fwd14/30：若 V 型反弹（预期如此，P 期 14d 91% 证据）→ 规则=「暂停新开仓 + 恐慌仓不砍（等止跌指纹）」；若续跌为主 → 规则=「组合降杠杆提示」；
  - **规则与探针结论绑定**，结论反转则规则反转，不预设。
- **输出**：`crash_flag`（含触发日/跌幅）+ `response` 文案 + 证据引用；展示=dashboard 事件响应条 + monitor 事件；该信号同时喂给组合层页面（组合降杠杆提示位，只提示不自动执行）。
- **验收**：探针产物入库 + 规则一致测试 + monitor 事件测试。

## 四、模块 C：时期监测自动化

- 现状：monitor 已有「大盘状态切换」事件（bucket 已用五时期标签，切换告警自动生效）。
- **本次补**：① 当前时期持续天数（进 dashboard 大盘信号卡）；② 时期边界季度重验台账——每季度复核 `_exp_market_periods.json` 的四切点稳定性 gap（≤6.5pp 警戒），只监测不调参；台账文件 `data/period_boundary_recheck.jsonl`（追加型）。
- **验收**：持续天数断言 + 台账写入测试（幂等）。

## 五、模块 D：大盘风险仪表

- **输入**：M1 字段（vol20 / breadth5 / dist_hi60 / dist_lo180），实时算（生产库）或取当日 market_state_daily 行。
- **数据缺口（本稿校验发现，已并入实现范围）**：生产侧 breadth5 尚未实时计算（M1 最新行只有 vol20/dist 字段，breadth5 仅回放期有过）——每日任务 `market_period.daily_state` 需补算 breadth5（HQ 池 5 日上涨品占比，复用 probe_market_base 的 breadth 逻辑，一次全池查询，秒级），与 vol20/dist 一并落当日 M1 行。
- **档位规则（预注册，来自已挖的时期指纹，非拟合）**：
  - 高风险：vol20 ≥ 3%（P 期 vol 中位 4.6% 的恐慌级）或 dist_hi60 ≤ −15%（60 日高点回撤 ≥15% 深跌中）；
  - 低风险：vol20 ≤ 0.7%（S1 慢牛指纹 0.68%）且 dist_lo60 ≥ −5%（贴 60 日低点上方）；
  - 中风险：其余。
- **输出**：`risk_level` + 三因子明细；dashboard「🛡 大盘风险」条。
- **验收**：三档边界测试 + 当前实盘值渲染。
