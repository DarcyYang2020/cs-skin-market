# 0. 架构总览

**目标**：CS 量化产品，6 层架构：

| 层 | 职责 | 设计状态 |
|---|---|---|
| ① 数据层 | 采集/处理/存储/分发 | 已出设计（§1）|
| ② 研究层 | 因子挖掘/特征工程/策略研究/模型训练 | 已出设计（§2）|
| ③ 交易决策层 | 信号生成/组合优化/仓位/风控 | 已出设计（§3）|
| ④ 交易执行层 | 订单/智能执行/市场成交 | 已出设计——**模拟盘模式**（§4）|
| ⑤ 评估层 | 回测/绩效/风险归因/策略迭代 | 已出设计（§5）|
| ⑥ 运维层 | 监控/日志/告警/权限审计 | 已出设计（§6）|

**六层设计摘要（v1.0 快速视图）**：

| 层 | 一句话核心 |
|---|---|
| ① 数据层 | 三层存储（原始/加工/派生）+ 单一事实源 + 版本冻结/oos_zone/恢复演练 + 规则配置化 |
| ② 研究层 | 因子=CS 专属 8 类分类+注册表+10 步挖掘流程；特征=六步加工+截面 rank/品类中性化；策略=四关管线+隔离评估+多策略倾向；模型=规则主干+ML 辅助（树模型）|
| ③ 决策层 | 组合四层框架禁优化器；信号"族=理由"；风控三层链（CS 特色：止损=事前仓位）|
| ④ 执行层 | 模拟盘+钉钉通知+人工执行（Steam 风控红线，绝不自动下单）；悠悠有品主渠道；买0/卖1 |
| ⑤ 评估层 | 回测质量门 5 项+绩效仪表盘（/evaluate）+风险归因+迭代循环（全走闸门）|
| ⑥ 运维层 | AUTH-1+交易级监控+kill switch 运维端+结构化日志/操作审计+告警分级 |

**5 个打磨点（2026-08-26 架构讨论定）**：
1. ④执行层 = 唯一不可回退层，且反向约束上游（薄流动性、平台约束）；
2. ⑤评估层 = 守门员非报表层（策略迭代须走预注册防过拟合）；
3. 风控跨层横切（③仓位/④订单限/⑥kill switch）；
4. 数据层补治理职能（版本/备份/血缘）；
5. CS 品类特殊性贯穿全架构（库存即资产、薄流动性回测、平台约束）。

# 1. 数据层设计（v0.1）

## 1.1 现状盘点（2026-08-26 核实）

| 事实 | 说明 |
|---|---|
| 采集源 | csQAQ chart API 唯一量源（价格+在售量，统一采集渠道非锚定平台）；定价锚 yyyp>buff>c5>steam（Steam 失真仅参考，不落主价） |
| 已有日采表 | price_history（1095 天）、bid_history（买侧）、item_fundamental_snapshot（turnover）、survive_history（存世量）|
| 周采样表 | bid_observations（点差，source='weekly'）|
| 质量机制 | 跨品一致性闸门（8/10 故障后建，超阈回滚+detail）、锚校验、健康检查+钉钉告警、3 年回填 |
| 关键发现 | csQAQ /info/good 已返回订单簿（buff_sell/buy/sell_num/turnover），collector 已解析 OrderBook——数据在给，落库不完整 |
| 已知教训 | 08-20 误删 283 文件；基线版本错配→103 假漂移；WATCH_GAP=6.5 无出处 |

## 1.2 采集

- **结论**：①价格×在售量引擎合理但降维使用（bid/spread/turnover 已采未用=富矿）②日 K 为单一事实源，时/周 K 派生不另采 ③执行层 Tier-1 盘口（最佳买卖价/点差/挂单量/日成交）csQAQ 现即可日采累积（历史盘口只能从现在积累，宜早）④情绪改用市场内生信号（点差/bid 强度/日成交/在售量变化；v0 用价格/在售量可回测部分，3-6 个月后 v1 加盘口因子）⑤**外部·事件/社区取消**（用户拍板）。
- **落库三缺口**：①price_history 加 `price_source TEXT` ②每日点差=派生（price×bid），不新采 ③bid_history 补卖侧列（lowest_sell/sell_count）。

## 1.3 存储

- **分层**：原始层（高价值数据独立 raw.db，append-only，订单簿/成交/存世量；价格历史不建）→ 加工层（market.db 权威，闸门/锚定在此）→ 派生层（回放库/特征矩阵/时周K/点差视图，**可重建不备份 git 不跟踪**）；
- **单一事实源三铁律**：日 K 唯一价格源；点差派生视图不单独存；口径唯一权威（config，C1 教训）；
- **技术选型**：保持 SQLite；升级触发条件（写进治理）：①并发写冲突常态化 ②单库>2GB 或查询退化 ③需多实例。

## 1.4 处理

- 四块：清洗/对齐/派生/留痕；**三铁律**：可复现（清洗函数确定性）/可追溯（每次清洗留痕）/不污染原始（原始层 append-only）；
- **规则配置化（已拍板）**：清洗规则（闸门阈值/锚定优先级/污染清单/新鲜度缺失率）进 config（带参数/出处/生效日期）；触警落 `data/cleaning_ledger.jsonl`，进健康检查统计。

## 1.5 治理

- **血缘（待③审计）**：行级（price_source+created_at+批次）＋派生级（provenance.jsonl：脚本/输入源/参数/时间戳/版本）＋数据版本（schema+时点+口径）；
- **恢复演练（待③审计）**：脚本化（restore_from_backup.py + rebuild_derived.py 幂等）＋台账 recovery_drill_log.jsonl＋每月一次全流程＋PRAGMA integrity_check+行数+抽样对比；
- **备份**：关键库每日 .bak 双副本，派生层靠可重建；
- **监控**：闸门触警统计/缺失率/新鲜度/备份成功率进每日健康检查。

## 1.6 分发

- 消费方：研究层（批量读派生层）/决策层（查加工层）/评估层（历史+交易）/执行层（未来准实时）；
- **四原则**：只读消费／**版本冻结**（回放基于冻结数据版本，103 漂移病根）／派生隔离／口径一致；
- 差距：版本冻结最弱，为第一补齐项；统一访问层不做。

## 1.7 补充项（用户认可）

1. **样本外封存（数据禁区）**：验证段（≥2025-08-10）与 B 通道窗口（~2027-04-25）标记 oos_zone，研究准入前不得窥探/调参（反过拟合硬落地）；
2. **数据不变量测试**：schema/范围/连续性/唯一性/日期不跳的独立测试套件，每日采集后+每次回填/恢复后跑。

## 1.8 明确不做

数据字典（data-layer.md 是事实源）、质量评分/SLA（监控已覆盖）、多环境副本、数据合规。

# 2. 研究层设计（v0.2）

## 2.1 定位与基调

- 四模块：因子挖掘 / 特征工程 / 策略研究 / 模型训练；
- **基调（用户明令）**：符合 CS 市场特点，不照搬股市量化（方法可参考，内容不可照抄）；
- 现状：方法论最成熟（预注册→族开回放→四关→③审计），因子治理空白，模型空白。

## 2.2 因子挖掘

**因子分类（修订版，按功能角色）**：

| 类别 | 因子 | 功能角色 |
|---|---|---|
| 价值/估值 | pct、z、估值网格 | 单票打分 |
| 动量/反转 | chg7/30/90、超跌反弹 | 打分+触发 |
| 趋势/技术 | MA 结构、趋势健康度 5 维 | 决策触发 |
| 供给/流动性 | sc7/sc30、s7_ratio、在售量、spread、bid | 单票打分 |
| 波动 | vol7/vol30、max_dd | 风险调节 |
| 量价交互 | 涨+供缩/涨+供扩 | 决策信号 |
| 情绪/另类 | 内生情绪代理 v0/v1 | 加分/过滤 |
| 市场环境 | 大盘指数、时期、mkt_chg30/th | 条件因子 |

**质量评估（口径已拍板）**：评估对象 10 组；**截面 IC + 14/30 双前向 + 时期分段 IC**；覆盖率为辅；供给类不做单调性硬判（看条件 IC）；**先不跑，全部确定后跑**；探索只许 fit 段（oos_zone 禁区）。

**组合测试**：增量 IC（新因子对现有因子正交化后残差预测力）＝"提供新信息"才算数；IC 相关 >0.8 视为冗余；组合用等权/IC 加权，**禁优化器**；IC/分层只是筛查，准入仍是四关。

**因子注册表（待③审计）**：`data/factor_registry.json`（机器事实源）+ md 视图；13 字段（id/name/category/role/definition/data_dependency/version/source/quality/status/in_engine/cs_note/tested_at）；生命周期=入库即登记→评估→状态流转（候选/生产/证伪，证伪保留防重复挖）；与 config（管参数，status=生产才可进权重表）/数据层（版本冻结取数）/③审计（核对清单）衔接。

**挖掘流程（启动清单，10 步）**：假设/品类映射 → 预注册 → fit 段 IC/分层筛查 → 相关性去重 → 增量 IC → 组合候选族 → 全池独立回放 → 四关 → ③审计 → 正负登记入注册表。

**新因子来源（按有效性）**：①品类映射（证券因子→饰品：换手率→在售量周转、市值→存世量×价格）②新信息源（内生情绪 v0/v1、steamdt 成交额候选）③假设驱动 ④数据驱动扫描（防照镜子+单月簇）。

## 2.3 特征工程

**六步流程（修订版）**：构造 → 缺失处理（提前，防污染后续变换）→ 去极值 → 标准化 → 中性化 → 平滑。

**CS 加料（三个口径 v0 暂定，用结果说话可调）**：
- 标准化 = **截面 rank/z 为主**（价格带差异+时期效应）；动量/供给比率类轻标准化；
- 中性化 = **价格带 + 品类**（AK 与手套不是一个市场，CS 版"行业中性化"）；
- 缺失 = **前向填充 + missing flag**（停更本身是信号；策略进 config）；
- 去极值：特征 MAD clip；**标签 net14 不去极值**（肥尾是真实行情）；
- 构造防前瞻（只用 T 日及以前信息）。

**特征质量评估两层**：①特征自身（覆盖率/缺失率/分布稳定性 PSI/区分度）②加工增值（每步前后 IC 对比，降了=破坏信息要调）＋相关矩阵去冗余；评估卡喂因子注册表 quality 字段。

**版本冻结**：特征矩阵带"输入数据版本+特征口径版本"（衔接数据层）；研究回放基于冻结特征版本。

## 2.4 策略研究

**流程（用户 5 步映射现有管线，管线审计补强 4 处）**：
```
假设提出 → 预注册（判据先行）→ 因子/信号组合 → 族开回放（全池独立）
→ 回测验证（完整四关）→ 稳定性检验（前后半段+置换+分时期）
→ 策略输出（③审计 → PM 立卡 → 研发落地 → 正负登记）
```
**补强 4 处**：①入口候选来源声明（独立扫描/预注册假设，无偏显式化）②回放输入版本冻结声明（103 漂移教训）③样本外封存硬约束（探索只许 fit 段，val 段预注册后才触碰）④落地挂监测（J-2/生命周期台账）。

**评估指标（延续 north_star）**：主=总收益+风险预算软约束+胜率下限；Calmar/maxDD=监控项；**Sharpe 不采纳**（肥尾/固定持有期/无风险利率失真）；辅=期望 per trade+信号量 n_trades。

**策略形态：多策略组合（倾向，数据说话）**——三条纪律：①每个子策略独立过四关 ②组合权重用简单规则（等权/风险平价），禁优化器 ③组合级样本外验证。过渡路径=策略隔离评估。

**策略隔离评估（v0 名单 6 族，名单可改）**：恐慌/深值/趋势买涨/供给/反转/基础——每族独立族开回放+四关（north_star 口径）+差异化三表（信号重叠/收益相关/时期覆盖）+组合测试 vs 单引擎；输出策略隔离评估表进生命周期台账；预注册/oos_zone/候选来源/正负登记。

**策略生命周期台账**：J-2 三通道升级为正式台账（候选→上线→监测→退役）；**退出策略议题暂挂**（卖出侧现为固定规则 hold21+跟踪止盈，待执行层盘口数据）。

**组合优化方法论（先定纪律）**：简单规则、禁优化器、样本外验证；具体权重研究等有多策略数据。

## 2.5 模型训练

**ML 立场**：**规则主干 + ML 辅助，ML 不进决策链主干**。理由：数据薄（按时期切有效样本少）、过拟合（ML+回测=过拟合放大器，纪律必须绑死）、regime 非平稳、可解释性（③审计要能看懂）。若用 ML 用**树模型**（LightGBM/XGBoost/CatBoost——匹配 CS 缺失/类别/交互/肥尾特性）。

**用途（用户拍板）**：
- **regime 软识别 = 做**（GBDT 或更简单模型，替代硬时期条件，预注册+样本外）；
- **内生情绪代理 v1 = 做**（候选组件=steamdt 饰品成交额：已核实页面有 ¥成交额/成交量/新增额/新增量/在线人数/大盘指数/板块指数，日级环比+单品 10min 级——作为**市场级活跃度组件**（真实成交数据，补"需求侧"维度）；前置=数据层采集可行性预研：可采集性/历史深度（决定能否回测）/与 market_index 相关性）；
- **信号排序辅助 = 不做**；**因子合成/权重学习 = 不做**。

**ML 纪律（缺一条不做）**：预注册（模型/特征/标签/切分/评估指标/与基线增量判据）/样本外（fit 训练 val 验证 oos_zone，B 通道）/可解释（可解释模型+SHAP 必报，③审计看不懂不上）/防过拟合（不反复调参、不网格择优落地）/版本冻结（模型+特征+数据三版本绑定）。

## 2.6 规则主干质量评估 = 体检系统（非一次考试）

- **分层归因**：信号层（6 族隔离评估+因子 10 组评估）／组合层（benchmark vs 等权/大盘+分时期质量表）／执行层（可成交性，执行层建立后接入）；
- **组件可替换**（"可能调整"的机制）：因子差→换因子；内生情绪 v1→替换 approx_sentiment；regime 软识别→替换硬时期条件；steamdt→新增市场级组件；替换后重评该组件+全链路回归；
- **全架构接口**：输入前提=数据层版本冻结/oos_zone/数据不变量测试；验证运行=评估层⑤+B 通道；监测=J-2 C 通道+生命周期台账；上限=执行层④可成交性；
- **触发调整闭环**：组件质量破阈值（预注册判据）→ 组件级复核 → 替换方案 → 预注册 → 四关 → ③审计 → 落地 → 挂监测 → decision-log+注册表状态流转。

## 2.7 研究层待定稿/待办

- 因子评估：对象 10 组已确认，跑之前需：评估脚本+注册表 schema 落法定稿；
- 策略隔离评估：预注册判据（每族四关通过线/相关性阈值/组合增益线）待定稿；
- 待③审计：因子注册表、管线补强 4 处、ML 纪律、血缘/恢复演练（数据层）；
- 数据层+研究层稳定后统一落 decision-log。

# 3. 交易决策层设计（v0.3）

## 3.1 现状

- 引擎本体所在层：六维评分（compute_value_score）+ 融合决策（decide_fusion_signal，家族化 buy 信号）+ 守卫链 1/2 + 供给扩张过滤 + 组合层（cap0.8/单票敞口 30%/熔断）+ 族级仓位网格（0.10~0.20）；**信号只有 buy，卖出=固定规则**（hold21+跟踪止盈 5%）。

## 3.2 组合优化

- **四层框架**：组合层（cap/总敞口/现金水位）→ 分配层（多策略/多族权重）→ 单品层（position_limit/单票敞口）→ 风控层（熔断/止损/kill switch）。
- **方法论纪律（先定）**：禁均值-方差/Markowitz/风险平价优化器/ML 权重学习（过拟合+薄样本参数不可靠，研究层"禁优化器"在此延续）；简单透明规则=cap0.8 沿用、分配=等权或 A2 期望加权（非优化）、单品=族级网格+单票上限、风控=熔断+止损。
- **权重调整纪律**：任何权重变化=新候选，走预注册→四关→③审计（v2-T10 式手工网格调参不再直接落地）。
- **CS 组合约束（三条）**：①单票仓位↔盘口深度联动（执行层接入后 position_limit 受可成交深度约束）②库存即资产（组合按实时市价估值、回撤按市值）③品类分散（枪械/手套/箱子联动，中性化的组合层延伸）。
- **多策略衔接**：隔离评估通过的子策略给固定权重（等权/A2 期望加权），组合级回测 vs 单引擎，数据说话。

## 3.3 信号生成

- **设计原则（核心）**：**"族=理由"，非"指标=信号"**——信号是市场行为/买入理由（恐慌抄底/深值修复/供给吸筹/趋势/反转/基础），不是技术指标状态；族=触发+守卫+仓位+持有完整行为假设单元；指标式信号（bull_steady 宽触发/rise_accum chg7 阈值）即被证伪路线。
- **四个决策（已拍板）**：①维持族制+预留策略抽象层（不动生产，隔离评估后数据说话）②触发/评分解耦=预留接口暂不改 ③信号强度→仓位（position_limit 从族级网格走向信号强度驱动）**暂缓**（等 A2 期望成熟+预注册）④流动性守卫等盘口数据积累（3-6 个月）后上（深度不足不发/降权）。
- 与执行层接口：信号输出带可成交性预期（薄流动性前置）。

## 3.4 风控跨层（CS 特色风控系统）

- **三层风控链（纵深防御）**：③决策层（守卫链1/2+供给过滤+cap0.8+单票30%+止损止盈）→ ④执行层（订单限额/滑点拒单/成交熔断/资金·库存校验）→ ⑥运维层（kill switch/告警/审计）。
- **四原则**：①纵深防御（同一风险多层设防）②不可绕过（执行层校验超限必须拒绝）③风控动作可审计（拦截/拒单/急停落台账，衔接数据层血缘）④kill switch 独立于业务链（上层卡死也能触发）。
- **kill switch**：两级（全局+策略级）× 双通道（手动+自动：连续拒单/回撤破阈/数据源异常/采集闸门触警）；自动急停本身进健康检查（"谁看管看门狗"）。
- **CS 风控约束（三条）**：①**止损=事前仓位控制为主**（薄流动性暴跌无接盘，仓位即止损，事中分批卖出/跟踪止盈）②卖出风控=库存校验（实物饰品先验有货）③黑天鹅不防（north_star 08-15 明示），管可防御回撤，黑天鹅靠仓位上限兜底。

## 3.5 评估层→决策层迭代反馈（用户强调，关键接口）

- **反馈环**：绩效评估 → 参数调整 → 模型更新 → 回流决策层各组件（信号/组合/风控/仓位）。
- **纪律（防环变质）**：反馈环不是自由调参——每一环都必须走**触发调整闭环**（组件质量破阈值 → 复核 → 预注册 → 四关 → ③审计 → 落地 → 挂监测）；参数调整=新候选；模型更新=预注册+版本冻结（模型+特征+数据三版本绑定）。**"绩效评估→参数调整"若绕过闸门，就是调参调到好看的过拟合（红线）。**
- 衔接：本环即研究层"规则主干质量评估体检系统"（2.6）与生命周期台账的组合；评估层⑤负责持续产出绩效，决策层按触发条件消费。

# 4. 交易执行层设计（v0.4）

## 4.1 定位（关键约束）

- **模式：模拟盘 + 通知 + 人工执行闭环**（用户明令，2026-08-26）：系统产出意向单 → 钉钉通知 → 用户人工判断/执行/回报 → 模拟账户更新。
- **红线：绝不自动下单**——Steam 风控封号风险（最高优先级，不可绕过）。
- 主渠道：**悠悠有品**；行情主口径：**csQAQ**（用户定）；悠悠有品数据=执行层补充（非主口径）。

## 4.2 闭环流程

```
决策层意向单（品/方向/数量/参考价/理由/期望/风控标签）
 → 钉钉卡片通知 → 用户人工执行/回报
 → 模拟账户更新（资金+库存）→ 评估层监测
```

## 4.3 模拟成交规则（用户定）

- 买入：**底价在售成交，0 手续费**；多数量也**都按底价**（v0 简化，已知偏差=真实市场多数量会吃掉多档挂单变贵，等悠悠深度数据积累后评估"深度递进"）；
- 卖出：**必须有货才能挂单**，按底价在售模拟成交，**卖出 1% 手续费**；
- 无"不发货/延迟"参数（用户定：默认能买到底价）；
- **费率（已拍板，评估层定）**：实际 买 0% / 卖 1%——回测口径改为不对称费率，历史回测重跑=执行待办（§7.2）。

## 4.4 悠悠有品补充数据（非主口径）

- 页面为 JS 渲染 SPA（WebFetch 实测拿不到），数据在内部 API——需 **Playwright 浏览器层**（拦截内部接口/渲染抓 DOM，项目已有基建）；
- 可采集：在售列表（底价/挂单分布）、求购列表、成交记录；
- 用途：模拟成交价校准 + 可成交性验证（决策层"流动性守卫"的数据基础）；
- 前置：立"**悠悠有品采集可行性预研**"（内部 API 逆向 + Playwright）。

## 4.5 台账与对账

- 模拟账户：资金 + 库存（持仓），每次成交更新；
- 成交记录（价/量/时/费率）落库——补**数据层"交易域"缺口**（订单/成交/持仓/资金表）；
- 与真实库存**可选**同步（用户回报后按真实校准）。

## 4.6 风控在模拟盘的形态（变形不取消）

- 限额/熔断/止损 → "**提示不执行**"（系统建议，人工决定）；
- kill switch → **暂停出单/暂停通知**（一键）；
- Steam 风控 → **人工确认闸门**（最高优先级）。

## 4.7 待办

- 悠悠有品采集可行性预研（立小卡）——详见收尾清单 §7.2。

# 5. 评估层设计（v0.5）

定位：**守门员（非报表层）**——回测验证 / 绩效分析 / 风险归因 / 策略迭代；展示结果一律带**质量标签**（展示≠证据）。

## 5.1 回测质量门（候选/策略准入前必过，5 项）

1. **时序特征平稳性体检**（ADF/KPSS，新增——防未来 ML/回归类因子伪回归；现有特征天然规避：差分/比率/截面分位，但需正式验证）；
2. **特征无泄露审计**（显式验证每个特征只用 T 日及以前信息；全周期标准化=泄露，z/pct 为滚动/截面需验证）；
3. **幸存者偏差核查**（回放池是否含"历史存在但后被淘汰/停更"的品——池历史回溯，衔接数据层池管理）；
4. **压力测试**（极端时期回测：2024-02 崩盘期 / 2025-10 回落期 / 流动性枯竭）；
5. **成本真实化**（不对称费率 **买 0 / 卖 1**（已拍板）+ 滑点模型，随盘口数据积累）。

## 5.2 绩效仪表盘（/evaluate 独立页，研究视图下）

- **三层展示**：①信号级（主界面：信号理由+该族近期胜率/期望——人工执行依据）②策略/族级（净值 vs 基准+回撤+胜率/期望/Calmar+月度热力图+收益分布）③因子/组合级（因子 IC/贡献/分层；组合 vs 等权 vs 大盘+分时期质量表）；
- **展示形态**：参考 OSkhQuant（交互式资金曲线/回撤/买卖点/月度热力图）——**只借形态，口径全是我们的**（north_star/分时期/分族/基准对比）；
- **质量标签纪律**：每条展示带"回测质量门状态"（四关/样本外/数据版本），未过质量门的不展示。

## 5.3 风险归因

- **收益归因**：按族/策略（信号数×平均期望）、按时期（bull/sideways/volatile）、按品类（枪械/手套/箱子）分解贡献；
- **回撤归因**：按时间（最大回撤时段）+ 按持仓（回撤期间 top 亏损持仓/族）；
- **集中度指标**：top5 单品贡献占比（>50%=集中风险警示）；
- **方法**：b1 组合模拟 closed 逐笔按族/时期/品类分组加总——直接可算，无需新模型；多策略 Brinson 归因（配置/选择效应）待多策略后上；
- **纪律**：归因=诊断工具，发现的问题走触发调整闭环，不直接改（防"看到就动"的过拟合式操作）。

## 5.4 策略迭代优化（迭代循环）

```
监测（J-2 C 通道+生命周期台账）──┬─ 被动：策略退化 → 退役/替换
                                  └─ 主动：研究新候选（隔离评估/因子挖掘）→ 增补
 → 预注册 → 回放 → 四关 → ③审计 → 落地（策略版本+1）→ 挂监测 → 登记 → 闭环
```
- **三纪律**：①迭代必过闸（禁"回测→微调→回测"循环）②方向数据驱动（被动=归因/监测，主动=研究候选，非随机试）③版本管理（策略 v+1，旧版本留痕可回滚，衔接数据层版本冻结）；
- 与已有衔接：触发调整闭环（§3.5）+ 生命周期台账（状态机）+ 隔离评估/挖掘流程（输入源）+ 反过拟合纪律（刹车）。

## 5.5 其他

- **模拟盘差异分析**：模拟盘（真实费率/真实成交节奏）vs 回测绩效偏差——最诚实的校准数据；
- **迭代反馈环**：绩效→参数→模型（§3.5，闸门纪律）；
- **费率口径修正**：买 0/卖 1 已拍板；**历史回测重跑校准 = 执行待办**（与回测质量门一起）；
- **展示位置**：/evaluate 独立页（研究视图下），主界面保持决策视角（信号卡片）。
