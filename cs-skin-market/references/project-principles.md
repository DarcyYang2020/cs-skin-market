# 项目三原则（所有改动的评判标准）

> 版本: v1.0 | 更新: 2026-08-03
> 来源: 用户定稿，后续所有方案/改动必须以此三条为准则。

---

## 三条原则

1. **破除散户魔咒**：将恐惧和贪婪抽象为计算符号（帮助止损/止盈/抄底等），避开散户凭感觉的弊端。
2. **数学模型代替主观直觉**：整体用数学模型代替主观直觉，相信概率与期望值的投资理念，寻求正期望值交易。
3. **止损不是割肉**：不需要每次都看对，只需要看错的时候少亏。止损是付费买一个正确的概率。

---

## 落地工作流（硬性要求）

### 算法改动必须数据先行
- **任何算法/参数/阈值改动，先用历史数据回测验证，再改代码**（用户多次强调"一切以数据验证结果为准"）。
- 回测数据起点：**2025-11-02**（10-24 五合一之后市场口径不同；历史数据测试也从此日期开始）。
- 优化目标：往更高胜率 + 更高期望值/盈亏比方向改；熊市侧重 **14d 胜率**（30d 权重降低）。

### 专家意见处理流程
1. 专家给出痛点/方案 → 先分析是否有道理，结合项目原则与已有代码，输出组合方案（不改代码）。
2. 用户确认测试哪些方案 → 先跑数据测试。
3. 数据验证通过（胜率/期望值提升）→ 再改代码。
4. 用户明确"按你的方案改"时，仍需先测试后实施。

### 风控参数上线标准（2026-08-06 新增，I-2）
- 任何**硬性风控参数**（单票上限、组合回撤熔断、并发仓位 cap 等）必须先过**组合回测**验证；
  回测不过的只能做提示层（不改信号、不拒绝）。
- 先例：单票 10% 硬上限回测被推翻（误伤 panic 大仓位，组合收益 +54.6%→+24.6%），改为只提示。
- B1 参数（熔断 10% / 单票敞口提示 30% / cap 0.8）列入**月度敏感性复跑**清单，样本扩大后复验。

### 信号族审计与事件上下文（2026-08-06 新增，I-3 教训）
- 展示/回测胜率必须带**独立事件数**（时间聚类去簇后），避免单事件高胜率被误读
  （先例：恐慌共振 42 信号全部集中在 2026-05-22~05-26 单次 V 型底事件，胜率 95% 无外推意义）。
- 新信号上线标准：A2 三件套（walk-forward OOS + 时间聚类 + 置换检验）缺一不可。

### 重拟合触发条件（J-2 修订，2026-08-07：恐慌事件不可控，改为三通道触发）
- 原门槛「≥3~5 个独立恐慌事件 + 2~3 个中性回升段才可重拟合」依赖不可控事件（实测 2025-2026 恐慌独立事件仅 2 个：2025-10 五合一、2026-05 恐慌深跌），缺乏可执行进度。重拟合触发改为三通道任一满足：
- A. 独立恐慌市场事件 ≥3（自然积累，不阻塞）
- B. 新数据累计 ≥260 天（约 2027-04-25，与参数冻结 OOS 复验点一致）
- C. 胜率监测触发：buy 连续 2 月 14d 胜率 <70% 或月度 14d<80%/30d<55%
- 事件不足时（当前 2 个）：引擎参数保持冻结，允许研究池 + 展示层探索（I-7 分桶复验等）；事件级验证用「市场事件 + 跨年度窗口外验证」（walk-forward）替代统计功效门槛。
- 事件簇纪律保持：生产按 ±3~7 天簇限次，单事件簇不调参。

### 工程规范
- 写中文必须用临时 .py 文件（UTF-8 BOM），不能 PowerShell heredoc/stdin（GBK 会转坏中文）。
- CRLF 文件（collector_csqaq.py / webapp/main.py）补丁需精确匹配，全部匹配成功才写盘。
- 服务重启：停 python 进程 → `Start-Process python run_server.py -WindowStyle Hidden`。
- 改动后跑 `tests/test_smoke.py`，通过后再提交。
