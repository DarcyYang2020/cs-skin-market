# 多窗口协作治理（2026-08-18 定稿）

> 目的：用多个 agent 会话窗口分工协作，替代"所有事挤在一个窗口"。
> 本文是**会话组织的单一事实源**，所有窗口开工必读；与 AGENTS.md「会话分工约定」互指。
> 底层纪律（预注册 / 反过拟合 / A2 三关 / J-2 三通道）不变，本文只管"谁在哪个窗口做什么、按什么顺序、交什么"。

## 一、四个窗口

| # | 窗口 | 角色 | 拥有 | 产出物 | 开工必读 |
|---|---|---|---|---|---|
| ① | **产品经理** | 方向盘 | 立项/路线图/优先级/验收 | `iteration-roadmap.md`、立项卡 | AGENTS.md + decision-log |
| ② | **算法研究专家（研究+研发）**（唯一长期） | 发动机 | 引擎/回测/探针/`pipeline`/`webapp` 代码 | 预注册探针、`_exp_*.json`、候选、落地代码、测试 | AGENTS.md + decision-log + terminology + iteration-roadmap |
| ③ | **审计**（独立） | 刹车 | 复核/证伪 | 审计报告、三关结论、置换检验 | 只读原始产物 + 预注册判据 |
| ④ | **运维**（短任务/自动化） | 维持 | 采集/监控/备份 | 日报、J-2 告警、数据健康 | data-layer.md |

> ②窗口由独立新会话承担，身份 = **算法研究专家（研究+研发）**；①PM 会话不兼任研究。开工 Prompt 见 `references/window-prompts.md` 窗口②。

## 二、三条铁律（架构红线，不可违背）

1. **审计独立**：③审计 永远独立于 ②研究+研发，**不得由同一窗口兼任**。这是"反过拟合"从口号变架构的关键——研究自己跑回测、自己判通过 = 既当运动员又当裁判，纪律再严也形同虚设。
2. **研究不自我认证**：②产出的是「候选」，不是「通过」。落地必须在③审计通过之后。②自己跑的回测只能说"样本内候选"。
3. **审计只认原始产物**：③只看 `_exp_*.json` 回放产物 + 预注册判据，**不读②写的结论**——防"先看结论再挑证据"。

## 三、版本迭代流水线（一次候选从生到落地）

```
①PM 立项          目标 + 预注册判据 + 验收标准（写立项卡）
   ↓
②研究+研发        预注册探针 → 回放 → 候选（样本内 = 候选，禁止直接落地）
   ↓ 候选 + 原始产物
③审计            三关：组合级 + 前后半段一致 + 置换检验 + 发射分布复算（A2 第五件套）
   ↓ 审计报告（通过 / 驳回）
②研究+研发        落地：改代码 + 测试 + 同步 config/terminology/PROJECT_STRUCTURE + commit
   ↓
④运维            监测：J-2 三通道 + C 通道胜率/期望 + 模拟盘
   ↓ 月度报告
①PM              验收：对照立项判据，不达标 → 回炉 或 证伪关闭（登记 decision-log）
```

## 四、研究顺序（②窗口内部，从底到顶）

`数据层 → 大盘引擎 → 单品引擎 → 组合层 → 展示层 → 监测层`

- 每往上一层，须以"完整引擎"做统一窗口回测，确认叠加后 ≥ 最优单层（AGENTS.md 算法改动四步）。
- 参数/阈值/持有期/仓位**不得在同一回放样本反复调参直至通过三关**；样本内只出候选，落地须样本外（B 通道 ~2027-04 重验）或 live pilot。

## 五、交接物（收尾必须落盘，不靠聊天记录）

| 窗口 | 必须交 |
|---|---|
| ②研究+研发 | decision-log 条目 + `_exp_*.json` 产物 + commit |
| ③审计 | 审计报告 + decision-log 审计条目（通过/驳回 + 依据） |
| ④运维 | 日报 / J-2 告警 / 数据健康检查 |
| ①PM | 更新 `iteration-roadmap.md`（立项/验收结论） |

**不写 decision-log 的改动视为未完成**；压缩/新会话后靠这些落盘物恢复，不靠聊天记录。

## 六、单一事实源（谁说了算，禁止各窗口各说一套）

| 问什么 | 看哪 |
|---|---|
| 决策/结论/为什么 | `references/decision-log.md` |
| 口径/数字/基线 | `references/terminology.md` + `config.BASELINE_LEDGER` |
| 文件结构 | `PROJECT_STRUCTURE.md` |
| 数据采集/表/任务 | `references/data-layer.md` |
| 三天内速览 | `references/two-day-synthesis.md` |

## 七、文件归属（防并行改同一文件冲突）

- `pipeline/`、`references/`、`tests/`：**②研究+研发** 拥有。
- `webapp/`（main.py、analysis_service.py、templates/）：②研究+研发 拥有（合并后不再单独归前端）。
- `data/`：④运维 采集写入；②研究 只写 `_exp_*.json` 研究产物；**任何窗口不得提交 `.db/.bak/.log`**。
- 同一时刻同一文件只允许一个窗口改；跨窗口碰同一文件前先在 decision-log 留言占坑。
