# 方案：废除成交量 · 以在售量 + 价格为核心重构（v1，2026-08-07）

> 决策人：用户（2026-08-07）｜状态：**全部批次落地（2026-08-07）**：P0 数据层去量 + P1 引擎去量 + P2 回测验证（v2，见 §9）+ P3 在售量增强 + P4 解冻，落地明细见 §9.1
> 关联：`iteration-roadmap.md` v17 ｜ `decision-log.md`「废除成交量·以在售量+价格重构」

## 0. 决策摘要

1. **彻底放弃成交量**：悠悠有品成交量采集（`collector_youpin.py` / `uu_headers.json` / 每日 `collect_volume` / 进度卡量区块 / 健康检查量项）全部停用并移除依赖。
2. **引擎去量**：流动性、趋势健康、周期、动量四处量触点改为不依赖成交量，权重重分配给价差、在售深度、动量与大盘。
3. **以在售量 + 价格为双核心**：供给侧用 `in_sale_count`（csQAQ chart 自带、无需登录态、94 品 × 约 1 年历史），需求侧用价格/估值/大盘，重建因子与信号确认层。
4. **解冻引擎**：撤销「等真实成交量 90 天积累」的冻结约束，退出参数定稿、量能确认 v2 关闭。
5. **验证**：458 信号基线本就是 `volume=0` 占位，去量后回放应零差异或仅展示层差异；再以真实 8 天量做消融对照确认无回归。

## 1. 背景与证据

### 1.1 量不加分的证据（仓库内已有）
- 引擎基线即无量：`run_item_backtest.py` 回放以 `volumes=[0]*len(prefix)` 占位，`references/engine-unified.md` 数据源表明确「真实成交量 <90 天未激活」，`references/trend_leg_research.md` 量能确认 v2 以 volume=0 占位。
- 模拟量激活实验（2026-08-06，`references/sim_vol_replay.py` → `data/sim_vol_replay_supply.json`）：灌入在售量×周转率模拟量激活整条量价链路后，458→474 信号，win14 64.2→63.3%、avg14 13.55→13.17、win30 67.3→66.2%、avg30 21.8→21.11，全面持平略降；新增 29 个 th=35 边缘 deep_value 信号质量差（win30 39.3%）。当时结论即「模拟量只激活链路不带来信息」。
- 代码已对量做降权保护：`trend_health.py` 真实量 <20 天量价项强制中性；`item_analysis.py` 量能打分需真实量 ≥20 天才启用。

### 1.2 量延误信号的证据
- 引擎冻结期：`AGENTS.md`「引擎冻结期（等真实成交量积累），不改任何信号引擎」；`item_analysis.py` 退出参数「定稿等成交量 90 天积累后」。
- 分析/批量扫描同步抓悠悠量（`webapp/main.py` `_fetch_volume_cached`），依赖约 10 天过期的登录态，token 失效当日采集熔断（`collector_youpin.py` code 84101）。
- 积累系统不可达：`collect_volume` 只 `UPDATE` 不 `INSERT`，非自选品价格行停更后量写不进去（实测 8/3 起每天仅 25 品有量），「等 90 天」按设计无法完成。

### 1.3 在售量（in_sale_count）的基础
- 数据源：csQAQ chart API 自带 `num_data`（在售量），与价格同源同链路，**无需登录态**。
- 现状：94 品、2025-08-04 ~ 2026-08-07、约 2.5 万行；历史覆盖远超成交量（8 天），可直接支撑回测。
- 已有使用：`supply.py`（7/30/90 日变化率、吸筹/派发）、K-2 供给扩张闸门（已验证正贡献：剔除 91 个供给扩张坏信号，win14 57.8→62.2%）。
- 已知缺口：与价格行同受「非自选品不每日刷新」限制（8/3 起每天仅 24~29 品有在售量行），P3 必须修。

## 3. 引擎去量 + 权重重分配（P1）

### 3.1 触点清单（共 4 处，全部为辅助/确认层，非入场触发）

| 触点 | 位置 | 现权重 | 改法 |
|---|---|---|---|
| 流动性·成交量 | `item_analysis.score_liquidity` 量 40% | 流动性评分内 40% | 改为 价差 50% + 在售深度 50%（低量品流动性风险由价差+深度+存世量兜底） |
| 趋势·量价项 | `trend_health._dim_volume` 16% | 趋势分内 16% | 删除；权重并入动量/趋势/波动项 |
| 动量·vol_spike | `item_analysis` 量能打分（真实量≥20 天才启用） | ±0.05~0.25 修正 | 删除；量能触发条件（日成交/30日均量≥3x）废弃 |
| 周期·量能 | `item_analysis._analyze_cycle` 量能萎缩/对倒判断 | 周期置信度修正 | 改为在售量萎缩判断（挂牌量变化比成交笔数更干净） |

### 3.2 评分表权重（AGENTS.md 五因子）

| 因子 | 现权重 | 新权重 | 说明 |
|---|---|---|---|
| 稀缺度 | 35% | 35% | 不变 |
| 成交量 | 15% | 0% | **废除** |
| 流动性 | 15% | 15% | 内部改为 价差+在售深度 |
| 大盘 | 25% | 30% | +5%（承接量因子） |
| 概率 | 10% | 10% | 不变 |
| 在售供给 | 0% | 10% | 供给变化率 + 吸筹/派发，替代量的信息位 |

> 注：最终权重以回放校准为准（P2 验证后定稿，避免拍脑袋）。

## 4. 以在售量 + 价格为核心的新因子框架（P3）

### 4.1 供给侧（在售量，核心新增）
- 保留：`supply.py` 7/30/90 日变化率、吸筹（收缩+价稳/涨）、派发（扩张+价平/跌）。
- 新增：**在售量 × 价格组合宫格**（供给维度与价格维度交叉）：
  - 收缩 + 上涨 = 吸筹强（持有/加仓偏好）
  - 收缩 + 下跌 = 流动性差/无人接盘（谨慎）
  - 扩张 + 下跌 = 派发（回避，已由 K-2 闸门覆盖）
  - 扩张 + 上涨 = 热度假象（验证后续承接）
- 换手率代理：CS 市场在售量即「可交易池」，其**变化率**比悠悠单平台成交笔数更稳定、更抗对倒，作为量的替代信息位。

### 4.2 价格侧（需求侧，保留并强化）
- 估值分位：30/90 日 pct + Z-score（`valuation.py`，不动）。
- 趋势健康：7/30/90 动量 + MA 交叉 + 波动率（去量价项后重定权）。
- 大盘上下文：TH/情绪/regime/chg30（`market_context.py`，不动）。

### 4.3 风险侧（保留）
- 存世量 guard（<3000 不建仓）、盘口价差/求购深度、稀缺度、K-2 闸门（供给扩张/阴跌/半山腰/去重/飞刀）。

## 5. 验证方案（P2）

1. **基线复现**：96品池（删除重复品 id=162 后）重跑基线 450 信号（`baseline450`）。**实际并非零差异**：去量 v1 452 信号、win14 65.5 vs 64.9%/avg14 13.85 vs 13.95——流动性/趋势权重重分配会传导至信号边界，方向中性（详见 §9 结果表）。
2. **真实量消融对照**：用 7/26~8/2 真实量窗口，含量 vs 去量同一回放对比 win/avg，确认去量不回归。
3. **test_smoke**：删除/改造 youpin 用例（`t_youpin_aggregation`/`t_youpin_auth_error`/`t_youpin_no_auth`/`t_volume_map_fill`）；新增在售量覆盖断言与「去量后流动性=价差+深度」断言。
4. **健康检查**：全部品（自选+非自选）每日在售量行数 ≥ 阈值，防止再现「只看自选」盲区。

## 7. 风险与边界

- **失去的信息**：成交活跃度（低量品的流动性风险会被高估）→ 由价差 + 在售深度 + 存世量 guard 兜底，文档注明。
- **在售量的坑**：在售量是挂牌量，可被庄家挂单操纵（大量挂单制造供给假象）；且不同平台在售量不同源 → 以 csQAQ chart `in_sale_count` 为唯一口径，吸筹/派发信号叠加价格确认。
- **数据缺口**：非自选品在售量行不每日刷新（P3 必修，否则与成交量同样的坑）。
- **历史归档**：`volume_day` 列保留（研究价值）；`uu_headers.json` 凭据与 `collector_youpin.py` 于 2026-08-07 终审删除，不再写入。
