# 第二批设计：全族边界重研究（C/D/F 重点）预注册

> 日期：2026-08-16 | 状态：历史设计，已被 `family-boundary-arbitration-v1.md` / `v2.md` 承接；本文保留预注册过程。
> 依据：用户裁定（decision-log Q）——分族思路正确但族边界需重研究、C/D/F 重点、横盘时长无先验（数据里挖）、
> 现有数据分不出就调整数据利用方式（不等待积累）、参数不过拟合、打磨出最好版本。

## 一、目标

把七族从「触发条件拼凑」升级为「走势段语义 + 可区分边界 + 族历史特征」的完整分类体系，输出：
1. 每族的**走势段定义**（可观测、可回放）；
2. 族间**边界仲裁表**（重叠走势段的判定优先级）；
3. 每族的**族特征卡**（接入第一批 family_feature_cards 基建）；
4. C（二波）、D（启动前发现）、F（反抽 vs 真反转）三个重点族的判别探针。

## 二、七族边界（候选语义，探针检验后定稿）

| 族 | 走势段语义 | 边界关键量（数据里挖，不预设值） |
|---|---|---|
| A panic_resonance | 崩盘底/恐慌坑：深坑+恐慌+止跌 | 坑深/止跌结构；与 F 的边界=「是否已确认止跌」 |
| B deep_value/supply_accum | 低位磨底/均值回归 | 分位带；与 C 的边界=分位高低 |
| C 二波 | 已拉起来→回调→横盘→承接足 | 回调深度带、横盘时长（1 天起，数据挖）、价差收敛、求购抗跌 |
| D 启动前/温和上涨 | 未启动或刚启动即被发现 | 供给收缩签名、量价温和度；与 B 的边界=位置与动量方向 |
| E panic_easing | 恐慌后次级修复 | 与 A 的边界=恐慌强度档 |
| F 反抽判别 | 阴跌/派发后急拉阳线：反抽还是真反转 | 承接质量、位置、大盘环境、拉阳前的派发强度 |
| G 风险态（派发/阴跌） | 卖点风险提示 | 供给扩张+滞涨；与 F 的边界=是否出现急拉 |

## 三、预注册判据（先写死，再跑探针）

1. **横盘时长**：不预设。探针第一步输出「回调后 1~20 日横盘窗口内，价差收敛(Δspread)与求购抗跌度的前视单调性」，从数据中找拐点，**拐点值仅登记为假设**，须池级 fit/val 双正 + 你的实盘确认才可进引擎。
2. **F 判别**：反抽 vs 真反转样本定义——阴跌/派发期（sc30 扩张 + 价格 30d 下行）后 5 日内单日/3 日涨幅超样本分布上分位。区分特征候选：承接质量（bid 抗跌）、拉阳量级、大盘环境、坑深。**判据=两组 14d/30d 胜率差≥15pp 且 n≥50；达不到→调整特征视图（用户裁定），不等待样本积累。**
3. **C 二波**：判定链 = 高位（分位带，数据挖）→ 真实回调（深度带，数据挖）→ 横盘/价差收敛 → 承接。每环先跑池级区分度，再拼链。
4. **D 启动前**：候选信号 = 温和上涨（chg7 慢）+ 供给收缩签名 + 低波动（数据挖波动档），重点防伪（对倒假缩）。
5. **任何参数值（阈值/窗口/分档）**：仅作假设登记；落地 = 样本外（B 通道/live pilot）确认，禁同样本网格择优直接进引擎。

## 四、交付顺序

1. 探针 1：C 族回调/横盘/承接三量在池级的分布与前视区分度（数据挖拐点）；
2. 探针 2：F 反抽 vs 真反转判别（重点：当前市场状态窗口检验）；
3. 探针 3：D 启动前指纹（最难，最后做）；
4. 全族边界仲裁表 v1 + 族特征卡接入单品报告（报告结构不变）。
