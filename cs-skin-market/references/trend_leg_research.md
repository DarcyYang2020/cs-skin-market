# 趋势腿研究：非恐慌上涨段的买入通道（A3，2026-08-05）

> 数据：price_history 101 品 580 天 + market_index 993 天；只读引擎回放，不写 DB。
> 脚本：`references/trend_leg_research.py`（W1/W2 窗口回测）、`references/trend_leg_robust.py`（全窗口分桶）。
> 原始数据：`data/trend_leg_research.json`、`data/trend_leg_robust.json`。

## 1. 问题与市场结构

全系统 buy 信号均为「恐慌抄底 + 均值回归」单策略族（P0-5/P0-8/P0-9/超跌例外/D方案/深值+企稳）。
本研究的核心问题：**非恐慌上涨段是否存在可验证的正期望买入通道？路由层如何选择开启哪条腿？**

指数结构（2025-09 起）：
- 2025-09~10-17：强势上行（chg30 +14%），10-27 崩盘（单日 -41%）
- **W1 = 2025-11-02~2026-01-23**：崩后修复段（指数 2058→2049 横盘上移，chg30 从 -19% 修复到 -10%），cycle 以 volatile 为主（46/83），avg_th=50、avg_sent=43 —— 用户强调的「非恐慌小牛」
- **W2 = 2026-01-23~2026-03-17**：1/23 探底 2049 → 2/6~2/7 下跌中继/企稳 → 反弹到 2293（+12%），3/10 cycle=bull、th=66 —— 「1/23~3/17 反弹段」
- 对照：2026-05-25 深底 1467（chg30 -25%）、2026-07 阴跌（chg30 -3~-9%）

## 2. 缺口验证（现有引擎并非盲区，但效率低）

| 窗口 | 现有引擎 buy（7天去重） | 14d net | 30d net |
|---|---|---|---|
| W1 | 55 个 / 24 交易日 | +7.91% | +25.42% |
| W2 | 59 个 / 20 交易日 | +4.63% | +5.33% |

修正原假设：**不是"上涨段完全无信号"**——崩后修复段引擎照样触底买入且表现好（W1 30d +25.4%）。
真正的缺口在 W2（无新恐慌、纯反弹段）：引擎 30d 仅 +5.33%，而趋势候选（S2 +22.5%、S3 +31.4%）。
即：**现有抄底族在趋势段的收益效率低，且错过主升浪启动前的位置（S3 在 2/11 提前埋伏，30d +31.4%）。**

## 3. 三候选信号（研究原型，price+in_sale only）

| 信号 | 定义 | W1 30d net | W2 30d net | 结论 |
|---|---|---|---|---|
| S1 突破 | 创20日高 + 前20日涨≥8% | **-1.97%** | +13.92%（单簇） | 修复段负期望，v1 舍弃 |
| S2 回踩 | MA7>MA30 多头 + 回踩 MA30±3% + 前10日涨≥4% | +15.45% | **+22.53%** | 双窗皆正、多簇，**v1 主信号** |
| S3 吸筹 | 在售7日均量≤30日均量×0.85 + 7日|涨跌|≤3% | +5.87% | **+31.42%** | W2 极强（启动前埋伏），**v1 主信号** |

- S2/S3 均带市场过滤（sent≤60 且大盘TH≥45）时表现更稳定；S1 过滤无效。
- 时间集中度：W2 的 S3 触发集中在 2026-02-11~03-04（单市场事件簇），S2 分散在 02-15~03-17 两簇。

## 4. 全窗口分桶（路由层依据，2025-11-02~2026-08-05）

**S3 吸筹：近全桶为正**（仅 贪婪+弱TH volatile 等 2-3 个小样本桶为负）：
- 最佳：sent<40(贪婪)|TH≥45|volatile 30d +40.5~+47.2%（win 88-90%）；中性|TH45-60|volatile +25.9%（win 74%）；恐惧|bear+th0 +19.3~+22.4%（win 82-90%）
- **结论：S3 是「趋势腿与抄底腿共用」的启动前信号，门控最宽松**；只在 sent<40 且 TH<45 禁入。

**S2 回踩：强选择性**：
- 正期望桶：中性|TH45-60|volatile 30d +40.1%（n=82）；恐惧|th0|bear +22.9%（n=74，与现有引擎域重叠）；恐惧|th0|volatile 14d +12.5%
- 负期望桶：贪婪|TH<60（-8.7~-12.2%）；恐惧|TH45-60|volatile/bull（-15.0%/-25.4%）
- **结论：S2 只在「中性情绪 + 中高TH」或「恐惧 + 深跌(TH<45)」启用**；贪婪与"恐惧但未深跌"禁入。

## 5. 路由层草案（v0，供 C1 落地实现）

```
大盘状态（sent / TH / cycle / chg30）→ 腿激活：
  恐慌期(TH<45 或 sent≥60 且未深跌)  → 仅抄底腿（现有 P0 族，不动）
  深跌恐慌(sent≥60 + TH<45 + 深跌)   → 抄底腿 + S3（吸筹提前埋伏）
  中性震荡(40≤sent<60 + TH45-60)     → S2 回踩 + S3 吸筹（趋势腿主区）
  修复/反弹(sent<60 + TH≥45 + chg30 回升) → S2 + S3
  强牛(sent<40 + TH≥60 + bull)       → 暂不新增 S1（样本不足，v2 再评）
  贪婪弱TH(sent<40 + TH<45)          → 全腿禁入（S2/S3 均负期望）
```

## 6. 结论与 v1 落地建议

1. **趋势腿成立，主信号 = S2 回踩 + S3 吸筹，S1 突破舍弃**。
2. **路由层是趋势腿的前提**：S2/S3 门控表直接来自分桶数据，禁止全时段开放。
3. **S3 与抄底腿有协同**：S3 在恐慌桶也正期望（+19~22%），可作 P0 族的"启动前前置信号"，需要与现有引擎做同日去重与相关性测试（避免双计）。
4. **v1 实现**（C1 阶段）：信号接入 `item_analysis.py` 新 P 系列（如 P1x 趋势族），复用 trend_health/supply 已有分（S2 用 TH+MA、S3 用供给收缩已有检测），路由门控用大盘 TH/sent/cycle（`build_market_context` 同口径）。
5. **量能确认 v2**：90 天成交量积累后，S2/S3 叠加"量能温和放大"条件再验证（当前 volume=0 占位）。
6. **风险**：W2 的 S3 是单一市场事件簇（2/11~3/4），跨市场事件泛化未验证；分桶 n 去簇后仍偏小；回踩 S2 在 W1 的 4 簇中 60% 集中于单簇。落地时必须有 A2 聚类报告约束 + 参数平台验证。

### 9.4 门控与路由启示

1. **S3 v1 门控在牛市窗完全不拦**（65=65，无「贪婪+弱TH」组合）——当前「禁贪婪+弱TH」只在恐慌/中性环境有效，**强牛段路由需新边界**：bull / TH≥60 时 S3 放行（主簇 +38~43）。
2. **S3 崩盘前夜守卫缺口**：cl2 负期望簇提示「供给收缩横盘 + 大盘崩盘临近」需守卫（观察项，n=8 单簇，不直接调参防过拟合）。
3. **S2 强牛腿只开回调桶**：bear/th45-60/chg30-8~0 最强，bull 桶平庸、sideways 禁入——路由层 S2 可设计为「牛市回调腿」。
4. **事件样本仍不足**：牛市窗主簇 80% 仍 flag；两窗合并后 S3 正常吸筹事件 = Feb 簇 + 8-9 月簇 + 若干小簇，J-2 门槛（≥3~5 独立恐慌 + 2~3 中性回升段）仍未达；牛市段补充的是「强牛吸筹段」样本，不能替代中性回升段验证。
